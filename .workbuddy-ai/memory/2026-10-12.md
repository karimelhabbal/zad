## Measured facts about that artwork (1024x1024 RGBA)
- Squircle baked into the alpha channel, field spans x/y **48..975**.
- Field colour ≈ **#0F4331**; diagonal gradient `#134F3A` (top-left) → `#0C3728` (bottom-right).
- Gold mark bbox **243..781** (538px, centred on 512,512).
- Faint hairline frame at x≈72 / x≈952 — only `r-b` ≈ -2..+12, i.e. barely above the field.
- **Gold vs field separates cleanly on `r - b`**: field -39..-28, mark +40..+139, thin AA band
  between. Extraction ramp used: `RB_FLOOR=25`, `RB_CEIL=60`, plus unmixing against the known
  field colour so AA edges keep no green cast.

## The one non-obvious geometry trap
Android crops the **108dp** adaptive layer to a **72dp visible circle**. So a mark filling
`f` of the layer reads as `f * 108/72 = f * 1.5` of what the user actually sees. My first
attempt reused the artwork's own 52% scale, which would have rendered at **78%** of the
visible circle — far bolder than the design's 57.5%. Correct layer fill = `0.575 * 72/108`
= **0.383**; shipped **0.40** (design-matched plus a small nudge for 48px legibility).
Verified: max mark radius 21.6dp, inside the 36dp visible and 33dp safe-zone radii.

## The hairline frame is deliberately NOT in the adaptive foreground
It sits at ~86% of the layer, so every non-squircle mask would clip it into a broken partial
ring. It IS present in the API<26 `ic_launcher.png` (the artwork verbatim, never masked).

# Session 4 — audio: missing reciters, progress bar, duration, error handling

## The actual root cause of "the chosen reciter doesn't work"
The catalogue was **hand-written with only 18 reciters**. The CDN actually serves surah-level
audio for **148 of the 176 advertised Arabic editions**. The reciter the user asked for,
**عبد الله المطرود (`ar.abdullahalmatrood`)**, was one of the ~130 that were simply missing —
so it could not be selected at all. Nothing was broken about the chosen reciter; the list was.

## Fix: generated catalogue from live evidence
- **New** `tool/build_reciters.py` → writes `lib/data/models/reciter_catalogue.dart`
  (**generated; never hand-edit**). It asks the API which editions exist, then issues a real
  Range request against `audio-surah/128/{id}/{surah}.mp3` for surahs **1, 9, 36, 78, 114**
  and keeps only editions answering 200/206 every time. 176 → 148 alive → **144 unique**
  after de-duplication by Arabic name. A 206 also proves Range support (= seeking works).
- 28 editions answer **403** and stay excluded: `ar.husary`, `ar.mahermuaiqly`, `ar.minshawi`,
  `ar.abdurrahmaansudais`, `ar.hudhaify`, `ar.muhammadayyoub`, `ar.ahmedajamy`, `ar.shaatree`,
  `ar.hanirifai`, `ar.saoodshuraym`, and every `-2` / `-surah` alias. Confirmed again — my
  original exclusion reasoning was right, just far too narrow.
- `reciter.dart` now imports the catalogue; `defaultReciter` is `static final` derived via
  `byId(defaultReciterId)` so it can never drift. Added `QuranReciters.search()`.
- The picker gained a **search field** (144 entries is not scrollable by hand) that reuses
  `arabicMatches`, so a name typed without harakat still resolves.

## Two real bugs found in my own audio code
1. **Changing the reciter while paused resumed the OLD recording.** `playSurah` treated
   "same surah + paused" as `resume()` *before* checking whether the reciter had changed, so
   picking a new voice appeared to do nothing. Now the reciter check comes first and the new
   edition is re-streamed.
2. **The error state was wiped by its own teardown.** `_fail()` sets `status = error` and then
   calls `_player.stop()`; that stop emits a `paused` event which reset the status, so the user
   saw "تعذر تشغيل التلاوة" for a frame and then "متابعة". The state listener now refuses to
   downgrade out of `error`.

## Error handling: fail fast instead of hanging 30s
`audioplayers` reports a dead URL by never emitting `prepared`, so it only surfaces after
`AudioPlayer.preparationTimeout` = **30 seconds** of spinner — and the thrown text
("Stream closed before it got prepared") contains no HTTP status, so `_describe` misclassified
it as a generic playback error. Added a **pre-flight probe** (`AudioProbeFn`, injectable):
a one-byte Range request with a 10s timeout, returning ok/missing/forbidden/offline. The body
is **cancelled immediately, not drained** — a CDN that ignored Range would otherwise stream a
whole ~116 MB surah just to confirm it exists. Errors now name the failing reciter.

## New capabilities
±10s skip, playback speed (0.75/1.0/1.25/1.5/2.0 via `setPlaybackRate`), retry button, and a
progress row that is **always present once a surah is loaded** — it renders as an indeterminate
bar until the platform reports a duration, then becomes a real scrubber. Duration shows `--:--`
until known rather than vanishing.
