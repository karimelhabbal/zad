# 2026-10-15

## ⛔ RULE: a Mushaf page is NEVER cropped

**Non-negotiable, project-wide. The user rejected the `BoxFit.cover` approach
outright** — «لا يجوز اقتطاع أجزاء من الصفحة». Cropping a Mushaf page is not a
layout trade-off, it is religiously unacceptable. Do not propose it, do not
implement it, do not offer it as an option behind a picker. `contain` (or any
fit that shows the whole sheet) is the **only** correct fit for the Mushaf
reader. A band of empty surface around the page is always preferable to losing
even one letter. If a future request is literally "fill the screen", the honest
answer is that filling vertically and showing the whole page are mutually
exclusive at this aspect ratio — say so, do not silently crop.

This lesson cost a revert. Anything resembling "trim the scan's margins" is
also out — the margins are the page.

## Mushaf page: vertical fill attempt → reverted

**Request (ar):** make the Mushaf page fill the whole screen — it already filled
the width, they also wanted it to fill vertically.

**What went wrong.** I offered `cover` as the recommended option and the user
picked it, but the deeper mistake was offering it at all. See the rule above.

**Change applied, then fully reverted** — `lib/features/quran/mushaf_reader_screen.dart`:
- `BoxFit.cover` → back to `BoxFit.contain`
- removed the `ClipRect` wrapper and `clipBehavior: Clip.hardEdge`
- `panEnabled: true` → back to `false` (a horizontal drag must stay a
  page-turn gesture, and at scale 1 with `contain` nothing is off-screen so
  panning has nothing to do)
- **not** restored: the original 6px `Padding(EdgeInsets.all(6))`. The user's
  complaint was cropping, not the margin. Dropping it is what makes the page
  reach the full width. Trivially re-addable if they want a thin gutter.
- Added an explanatory comment at the `Image.file` call stating why `contain`
  is the only permissible fit, so this is not "helpfully" changed back later.

Verified after revert: no `BoxFit.cover` / `ClipRect` / `Clip.hardEdge` /
`panEnabled: true` anywhere in the file; `python tool/check_dart_balance.py`
passes.

**Measured facts (verified, do not re-derive).**
- Every page image served by `MushafRepository` is **622×917**, ratio 0.678.
  Confirmed on pages 1, 2, 3, 100, 604 (primary source `quran.ksu.edu.sa`).
  The printed Mushaf is *taller* than any phone screen, so `contain` fits the
  page to the screen **height** and centres it → the page fills the full
  height, with empty surface to the left and right in RTL (and the scan's own

## Why other Quran apps look edge-to-edge, and why we can't copy them

**Investigated 2026-10-15 at the user's request ("تطبيقات القرآن الصفحة معروضة
ملأ الشاشة تماما لماذا لانستطيع فعل هذا").** Answer: they do NOT display the
printed page full-screen — they **regenerate** it at a different aspect ratio.

**The actual mechanism (read from their source, not inferred).**
`github.com/quran/quran.com-images`, file `lib/Quran/Image/Page.pm` line 62:
```perl
$page->{height} = $self->{_width} * Quran::Image::PHI * $fontdelta;
```
`PHI = (sqrt 5 + 1) / 2` = 1.618 (golden ratio), defined in `lib/Quran/Image.pm`.
So every quran.com page is built at ratio **0.618**, not the printed 0.678, and
they can render at any width (`generate.pl --width 1300 --pages 1..604`).
Their own source notes `TODO: determine font size algorithmically and trim page
height to fit or force fit`. **Nothing needs cropping because it is drawn to
size in the first place.** That is the whole trick.

**Why we cannot copy it.** Two independent blockers:
1. They compose from the King Fahd Complex (KFGQPC) **fonts** + per-glyph
   bounding boxes in a MySQL DB — i.e. they re-typeset the Mushaf. That is a
   full layout engine, not a display change. Zad deliberately uses
   *photographs* of printed paper (`MushafRepository`), and
   `mushaf_reader_screen.dart` explicitly promises "never fabricates or
   re-simulates a Mushaf page with ordinary Arabic text".
2. The fonts are actively copyrighted. `quran.com-images` README, verbatim:
   *"The code is copyleft GPL (read: free) but the actual fonts and pages (in
   the `res/fonts` directory) belong to the King Fahd Quran Complex in Saudia
   Arabia."* (Also `license: null` on the repo itself.) The font copyright
   travels with the rendered pixels, so hosting the PNGs is the same exposure
   as shipping the TTFs.
   QUL/Tarteel (`TarteelAI/quranic-universal-library`) is **MIT for the code
   only**; the bundled QCF fonts are still KFGQPC. QUL publishes Mushaf
   *layout data* + fonts, and a "Quran script images" collection — **no
   604-page image set with a redistribution licence**, and `qul.tarteel.ai`
   has no public REST API (all `/api/v1/*` probed → 404).

**Asset survey result: no viable free-licensed page set at a phone-friendlier
ratio exists.** Measured (not from docs):
| set | dims | ratio | licence |
|---|---|---|---|
| KSU scans (`png_big`) — current | 622×917 | **0.678** | none stated / © KSU |
| `Kader4658/Quran_Pages` — current fallback | 1024×1656 | **0.618** | **`license: null`, no LICENSE file** |
| quran.com render | 1024×1656 | 0.618 | derived from © QCF fonts |

KSU offers only `png_big`; `png/`, `png_small/`, `jpg/`, `png_mobile/` all 404.

⚠️ **Risk already in the codebase:** `MushafRepository.fallbackUrl` points at
`cdn.jsdelivr.net/gh/Kader4658/Quran_Pages@main/page{NNN}.png`. Its PNGs are
**byte-identical to quran.com's output** (md5 `aea75d98ba3d06fb1c3e948a24fba54a`
for page 1) — i.e. it is a re-host of the QCF-font render with **no licence of
any kind**. The agent claimed md5 equality with quran.com's own files but I
only verified the Kader4658 side (`colortype=3` indexed palette, `bitdepth=4`,
confirming a flat font render rather than a scan). Separate concern, needs a
decision before any public release.

**The one clean path** to a 0.618 ratio is written permission from KFGQPC for
the QCF fonts/pages — which is exactly what quran.com obtained (their Tajweed
font notes "after receiving permission from both" KFGQPC and Dar Al Marifa).

**Conclusion to give the user:** filling the screen and showing the whole
printed page are mutually exclusive with a scan at 0.678. Do not promise
otherwise. Remaining honest options are UX-side: a width-filled vertically
scrollable reading mode (standard in Mushaf apps, crops nothing), or making the
band useful (peek the adjacent pages, or put the surah/juz/page context there).
