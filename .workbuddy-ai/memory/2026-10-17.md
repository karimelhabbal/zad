## Recitation: hide the player bar, choose surah or ayah, audio downloads

- **Ayah-level audio** — `QuranReciter.ayahAudioUrl(globalAyah)` →
  `cdn.islamic.network/quran/audio/128/{id}/{n}.mp3` (same host/edition/licence
  as the surah files). Verified live: 1..6236 all answer 206, 6237 answers 403.
  `QuranData.globalAyahNumber(surah, ayah)` (memoised prefix sums) reproduces
  that numbering exactly — 2:255 → 262, 3:1 → 294, 114:6 → 6236, and the real
  asset still totals 6236 ayahs.
- **`AudioController`** now has `RecitationScope {surah, ayah}`. `playSurah`
  and `playAyah` both funnel into one private `_load()`; "same track" includes
  the scope and the ayah, so switching between the two reloads. An ayah hands
  over to the next ayah of the surah (`_autoAdvance` / `_advanceAyah`) unless
  `continueThroughSurah: false`. Added `reloadWith(reciter)`,
  `setContinueThroughSurah(bool)` and `dismiss()` (idle + forget the track —
  what the strip's X does; `stop()` keeps the track and only pauses).
- **UI** — `RecitationBar`/`showRecitationSheet` deleted. `ListenBar` renders a
  single "استماع" button while nothing is loaded, then a slim now-playing strip
  that opens `showListenSheet` (scope switch, ayah list with a snippet per row,
  continue switch, `RecitationTransport`). `RecitationTransport` is
  track-agnostic. The text reader's ayah sheet has "listen to this ayah" first.
- **Downloads** — `AudioDownloadsController` (+ provider in `app.dart`) reuses
  `AudioController.cache`, so the manager and the player share one folder. New
  `lib/features/more/audio_downloads_screen.dart` replaces the Mushaf-about
  destination in More (about-Mushaf stays in the reader's overflow menu).
  `RecitationCache` gained `sizeOf`/`remove`; both fakes updated.
- **Cache-name bug fixed** — `fileNameFor` used the last TWO path segments, so
  `audio/128/ar.alafasy/1.mp3` and `audio-surah/128/ar.alafasy/1.mp3` collided
  (`ar.alafasy__1.mp3`): a cached surah would be served for a single ayah. Now
  the last FOUR are used. Old names become orphans that LRU eviction reclaims.
- Verified: `flutter analyze` clean, `flutter build apk --debug` succeeds,
  `tool/audio_harness/run.py` 57/57 (12 new ayah/dismiss/cache-name checks),
  `tool/verify_offline.dart` 135/135 (l10n parity included).



## Senior UI/UX review + fixes (whole project)

Reviewed every screen as a designer, then implemented the findings.

- **Hero colours are now design tokens.** `ZadTokens` gained `heroOn`,
  `heroMuted`, `heroGold`, `heroGoldInk`, `heroTrack` — identical in light and
  dark, because the emerald hero gradient is dark in both. Replaced every raw
  `0xFFEDBF7A` / `0xFF9FC0B1` / `0xFF8FAEA0` / `0xFFCFE0D7` / `0x33FFFFFF` /
  `Colors.white` on the hero surfaces (home `_PrayerHeroCard`, prayer-times
  card, quran `_ContinueCard`, `_AppCard`, azkar progress card). Only
  `app_colors.dart` defines these hexes now.
- **`ZadBadge` had an invisible label on dark surfaces** — it tinted the border
  and icon but drew the label in `onSurfaceVariant`, which is derived from the
  *page* background. Added a `foreground` override; the hero badges pass
  `heroGold`.
- **"صفحات اليوم" was lying.** It showed `quran.position.page` — on page 300 it
  claimed 300 pages read today. Added `QuranRepository.loadPagesToday` /
  `recordPageRead` (day-keyed set in `zad.quran.pagesToday.v1`),
  `QuranController.pagesToday`, fed by `savePosition`. Dropped the `/ 604`
  denominator: a daily count is not progress through the Mushaf.
- **Tasbeeh counter had no feedback and no undo.** Press-scale via
  `onTapDown/Up/Cancel` + `AnimatedScale(0.965)`, long-press to undo
  (`TasbeehController.decrement`, never below zero), richer `Semantics`
  (value + hint), and the hint line now teaches the gesture.
- **False affordances removed.** The surah row's bookmark `IconButton` looked
  like a toggle but opened the bookmarks list — it is now a non-interactive
  gold indicator (`quran.bookmarked`), and the duplicated trailing page number
  is gone. The home bell popped a *build-time* note at the user; it now opens
  the notification preferences.
- **RTL.** More screen's `chevron_left` was hard-coded; it now follows
  `Directionality`.
- **Greeting card** stacked two greetings ("صباح الخير، طاب يومك…"). Subtitle is
  now `home.subtitle` alone; `home.greeting*` keys removed (ar + en).
- **`showZadConfirm`** defaulted its confirm label to `tasbeeh.confirm`; added
  `common.confirm` and pointed the shared dialog at it.
- **Shell** rebuilt a post-frame measurement on every build; `_dockHeight` is a
  `ValueNotifier` published through a `ValueListenableBuilder` and the dock is
  measured from `performLayout` via `_MeasuredSize`.
- Verified: `flutter analyze` clean, `flutter build apk --debug` succeeds,
  `tool/audio_harness/run.py` 57/57, `tool/verify_offline.dart` 135/135.

### Real notifications (flutter_local_notifications 22.3.2)
- Deps: `flutter_local_notifications`, `timezone`, `flutter_timezone`.
- `android/app/build.gradle.kts`: `isCoreLibraryDesugaringEnabled` +
  `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.5")` (the
  plugin needs it for java.time below API 26). AGP 9.1.0 / Gradle 9.3.1 is far
  above the plugin's 8.11.1 floor.
- Manifest: `RECEIVE_BOOT_COMPLETED`, `POST_NOTIFICATIONS`, `VIBRATE`, plus
  `ScheduledNotificationReceiver` and `ScheduledNotificationBootReceiver`.
  Verified in the merged manifest.
- `android/app/src/main/res/drawable/ic_stat_zad.xml`: bookmark-ribbon vector
  for the status-bar icon (a mipmap would render as a white square).
- `lib/data/services/notification_service.dart`: singleton, **best-effort** —
  every entry point swallows its errors and reports a bool. Rolling 7-day
  window of concrete instants (prayer times drift daily, so a
  `matchDateTimeComponents: time` repeat would walk away from the real time).
  `AndroidScheduleMode.inexactAllowWhileIdle` on purpose: exact alarms need a
  permission Android 14+ users refuse, and a few minutes late beats never.
  Ids: `1000 + day*8 + slot.index` for prayers, 200/201 for adhkar.
- `lib/features/shell/notification_bridge.dart`: mounted under
  `MaterialApp.builder` (it needs both the localisation and the controllers).
  Syncs on a **signature** of (toggles, reminder time, method, madhab, high
  latitude, locale, lat/lng, city) — `PrayerController` notifies once a second
  for the countdown, so listening to it directly would reschedule every tick.
  Debounced 600 ms.
- Permission is requested **when a toggle is switched on**, never at launch; if
  refused, the switch stays off and a snack explains why. Enabling prayer
  reminders without a usable location still saves the preference and says so.
- `settings.notificationsNote` rewritten: it was a build-time developer note
  shown to users.
