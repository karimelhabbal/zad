# 2026-10-21

## UX / workflow audit of the whole app (read-only, no code changed)

Inspected every screen + controller. Report written to
`docs/ux-audit-2026-10-21.html` (Arabic, RTL, dark). 27 findings.

Findings that are worth remembering as *facts* (they constrain future work):

- **Azkar progress never resets daily.** `azkar_repository.dart:125` stores a
  plain `categoryId:itemId -> int` map with no day key, unlike
  `tasbeeh_repository.dart:109` which carries `dayKey` + `rollTo()`. So
  `home_screen.dart:556` ("أذكار اليوم") shows an all-time number. Not yet fixed.
- **Home rebuilds entirely at 1 Hz.** `prayer_controller.dart:61` ticks every
  second and `home_screen.dart:49` watches it at screen level.
- **Quran hub inline search is dead outside the Surahs tab** —
  `_JuzList`/`_PageGrid` (`quran_screen.dart:171`) don't take the query.
- Two search surfaces: `search_screen.dart` and the hub's inline field.
- Mushaf reader's "appearance" button calls global `setThemeMode`.
- Notifications: 7-day horizon only, rescheduled on launch only; no
  `onDidReceiveNotificationResponse`, so tapping a reminder lands on splash.
- No `PopScope` in `app_shell.dart` → back exits the app from any tab.
- Splash requires a tap on "ادخل" every launch.
- `pagesToday` counts distinct pages *opened*, not pages read.
- No background audio (deliberate, documented in `audio_controller.dart:943`) —
  flagged as the single biggest product gap for a Quran app.
- No wake lock, no recitation-follow highlighting, no adhan sound, no
  tafsir/translation, no backup/export, no khatmah plan.

Recommendation order agreed in the report: Wave 1 = the small correctness/flow
fixes; Wave 2 = notification horizon, real reading metric, background audio,
follow-recitation, unified search, page/juz index; Wave 3 = product expansion.
